# Roadmap de presentación pública — PacePal

Este documento recoge los siguientes pasos para dejar PacePal preparado como repositorio visible dentro del perfil profesional de GitHub.

## Objetivo

Convertir el repositorio en una evidencia clara del Trabajo de Fin de Grado y del proceso técnico seguido durante el desarrollo.

## Bloque 1 — README profesional

Estado: en progreso.

Tareas:

- Actualizar descripción del proyecto.
- Explicar el contexto de TFG.
- Presentar stack técnico real.
- Documentar funcionalidades principales.
- Mantener instrucciones de instalación local.
- Ordenar ramas principales y estado actual.

## Bloque 2 — Revisión pública

Estado: pendiente.

Tareas:

- Revisar archivos locales o temporales.
- Revisar documentación histórica.
- Confirmar que los datos incluidos son aptos para repositorio público.
- Revisar carpetas generadas por herramientas.
- Mantener solo lo que aporte valor técnico o documental.

## Bloque 3 — Capturas y demo

Estado: pendiente.

Tareas:

- Crear carpeta `screenshots/` si no existe.
- Añadir capturas de la landing, rutas, actividades, tienda, perfil y administración.
- Documentar cómo generar el build.
- Revisar configuración de GitHub Pages si se decide activar demo pública.

## Bloque 4 — Issues y mejoras

Estado: pendiente.

Tareas:

- Crear issues pequeñas por mejora.
- Mantener commits descriptivos.
- Usar ramas tipo `docs/`, `fix/`, `feature/` o `chore/`.
- Cerrar cada mejora con pull request.

## Criterio de cierre

El repositorio estará listo para fijarse en el perfil cuando tenga:

- README claro.
- Instalación local entendible.
- Capturas reales.
- Estado del proyecto explicado.
- Documentación accesible.
- Historial de mejoras organizado.
